## 📋 Overview

**Vehicle Service Management** is a low-code case management application built on Pega, designed to digitize the full lifecycle of a vehicle service request — from the moment a customer books a service, through inspection, cost estimation, customer approval, technician assignment, and final resolution.

The application was scaffolded using **Pega Blueprint** and then extended with custom data models, calculated fields, and skill-based routing logic to reflect real-world garage/service-center operations.

## 🧭 Case Lifecycle

The case flows through five sequential stages:

```
Create → Inspection → Approval → Service Execution → Resolution
```

1. **Create** — Customer submits Vehicle ID, Vehicle Model, and Issue Description to raise a service request.
2. **Inspection** — A technician inspects the vehicle, logs inspection notes, and assigns a condition rating.
3. **Approval** — Labor Cost + Parts Cost are captured and auto-summed into a Total Cost, which is sent to the customer for approval or rejection.
4. **Service Execution** — On approval, the case is auto-routed to the right technician queue based on vehicle type, and service status is tracked.
5. **Resolution** — On completion, the case closes and an automated email notifies the customer.

## ⚙️ Key Business Logic

### Automated Cost Calculation
A **Declare Expression / Calculated Field** automatically computes:

```
Total Cost = Labor Cost + Parts Cost
```

This removes manual math from the technician's workflow and guarantees the customer sees an accurate, consistent estimate every time.

### Skill-Based Routing by Vehicle Type
During **Service Execution**, cases are routed automatically:

| Condition | Destination Queue |
|---|---|
| Vehicle Type = "Truck" | `HeavyVehicleQueue` |
| Otherwise | `LightVehicleQueue` |

This ensures each job lands with technicians who have the right skills and bay equipment, without any manual hand-off.

| Goal | 2 days |

## 🛠️ What Blueprint Generated vs. What Was Custom-Built

**Generated by Blueprint:** the base case lifecycle (Create → Inspection → Approval → Service Execution → Resolution) and the initial data object skeleton.

**Built/customized manually:**
- Added specific properties (Vehicle ID, Vehicle Model) to the Create-stage view
- Configured the custom Total Cost formula
- Built vehicle-type-based routing logic to work queues (rather than the default operator-based routing)
- Corrected the Service Execution routing — Blueprint had defaulted assignments to a specific operator; this was reconfigured to route to `HeavyVehicleQueue` / `LightVehicleQueue` based on a Vehicle Type condition

---

## 🧠 Design Decisions

**1. Automated Cost Calculation**
Removes manual arithmetic for technicians and guarantees the customer always receives a precise, error-free estimate.

**2. Skill-Based Routing by Vehicle Type**
Different vehicle sizes need different mechanic skill sets and garage bay equipment — automatic routing avoids delays from manual case transfers.

---

## 🚧 Biggest Challenge

Getting the **Service Execution** routing to correctly target work queues instead of individual operators. The fix involved opening the Business Logic configuration, removing the default operator-based condition, and explicitly setting both the "Truck" condition and the "otherwise" path to route to `HeavyVehicleQueue` / `LightVehicleQueue`.

---

## 🔮 Possible Extension

If the approval step should only trigger above a certain Total Cost threshold, the Approval step's start condition could be changed from "always start" to a custom condition (`Total Cost > threshold`) — automatically bypassing approval for low-cost services.
